# 共享业务助手：附件与私有方案候选（2026-09-26）

一个共享 Codex 安装/服务承载多个独立用户任务，不共享用户会话、权限或业务事务。
本文是候选实现与验收边界，不是生产开放或全业务完成公告。

## 附件

普通业务对话现在接入原生私有 File 上传，首批仅 TXT、CSV、XLSX，单文件不超过 2 MiB。
HTTP 只接受 File 编号；服务读取原生文件及关联单据权限，绑定内容摘要、元数据修订和任务。
模型只可分页读取本任务绑定附件，不获得任意文件路径、下载地址或 File 目录权限。
每次读取及历史回放重新检查原账号权限；文件内容不是指令，不执行公式。

服务对 CSV/文本编码、XLSX 压缩包/XML、工作表、记录数及输出长度设置明确边界；超界拒绝，
不悄悄截断后声称完整分析。XLSX 使用 defusedxml 和 openpyxl；项目依赖已声明。
本次只在独立 QA 的 `python-deps-attachments-v1` 安装 defusedxml 0.7.1，未修改生产 Python 环境。

上传不是保存/发布业务的授权；只有用户明确要求时才调用已接通的原业务操作。PDF、图片/OCR、
旧 XLS 尚未接入普通对话；管理员原上传路径没有在本批改成这些限制。

发送响应丢失时保留原 request_id 和 File 编号，不自动重新上传/办理。仅原服务明确返回
`business_request_not_accepted=true` 的格式错误允许直接纠正重发；普通 HTTP 417 不代表未接收。
已终结任务的文件失效不阻断其他授权历史；失效任务内容不回传，未排空的任务也不假装结束。

## 新业务方案

普通任务可调用 `proposal_create/read/update/list`，复用现有 v1/v2 有限蓝图校验。
固定私有目录 `<sites>/<site>/private/business-codex/proposals` 必须由管理者预先配置为 0700；
缺少目录时此能力关闭，不影响既有任务历史/取消。数据库不得挂载给模型。

草稿按站点和所有者隔离，版本内容不可变，更新要求读取的 expected_revision；重复工具调用
返回原版本，不生成第二份。左侧 `business_proposal` 显示字段、状态和明确未启用提示，
没有结构启用按钮。原管理员 `business_blueprint` 权限不放宽。

提案与 Link 依赖加入任务完整来源集合；权限撤销后阻止模型交付、SSE 回放和预览。
SQLite 草稿写入与永久任务关闭标记处于同一数据库事务边界；取消/终态必须成功关闭并等待
既有事务完成。数据库忙或 I/O 异常不是“已经排空”的证明，关闭后不能重新开放旧任务。

指定管理者交接和复制至其原生私有 File 的后台方法已经实现：固定接收者、用途、版本，
未知提交结果禁止盲目重试。**后续候选已连接 HTTP/UI（见下节），仍未完成真实网页交接、
启用与普通账号使用闭环。**
原蓝图默认 System Manager 权限未改变；建表、启用、授权使用和保存业务记录是不同结果。
复杂财务/库存/外部接口不能用有限字段蓝图冒充完整实现。
