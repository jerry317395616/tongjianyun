# Tongjianyun 班级 3D 工作台 — 产品与技术设计

本文件是本功能的唯一设计与交付说明。2026-09-23 从“3D + 周边看板”升级为
“场景主工作台 V1”。空间对象负责选择业务上下文，场景内浮层负责清晰地录入和核对，
Frappe 原业务继续负责权限、数据与流程。本文明确区分已实现能力与后续范围。

## 产品与入口

功能位于 `tongjianyun`，浏览器入口 `/tongjianyun-classroom`。
业务工作台、已保存且启用的班级表单均提供“班级管理场景”按钮。
支持 `?class=<Student Group.name>&day=YYYY-MM-DD` 定位班级和业务日期。
班级参数在服务端重新验证，不能用改 URL 的方式越权。

页面默认是全屏卡通教室，不再以侧边菜单、外围指标卡片作为主要操作界面。
顶部只保留班级、日期、刷新与账号；主业务均由教室物件发起，在同一页面浮层中处理。
“所有物件”、搜索及键盘入口与3D物件使用同一份操作索引，作为无障碍及降级入口。
界面品牌使用现有“童健云”，不创造另一套园所资料。
班级名称、名册和业务状态均从当前站点读取；初次访问不生成示例学生或默认考勤。

## 场景主工作台 V1 交互设计

### 统一物件模型

`public/classroom/objects.js` 是唯一业务物件索引，当前包含11个物件：
门口点名台、学生储物柜、请假登记簿、教学黑板、班级餐桌、阅读小屋、
美工画架、午休小床、健康资料柜、家园信箱、教师工作板。
每个物件有唯一 `id` / `action`、名称、图标、示意坐标、说明与强调色。
Three.js 模型拾取、HTML锚定标签、文字搜索与“所有物件”面板复用相同的业务动作。
物件坐标不参与任何后台判断，拖动视角、选中模型或切换物件不会写入数据。

学生对象绑定 Frappe Student 的业务主键。虚拟人物的外貌是通用图形，不由姓名、
照片或敏感特征推断；登记状态通过环与文字表达，不把表情当作情绪数据。
实际人物射线拾取可打开业务卡片；卡片可进入考勤、用餐、成长记录和家园联系。

### 场景内浮层

桌面采用非模态右侧浮层：可在保留课堂上下文的同时点击其他物件。
复杂核对表格允许展开浮层；文字输入始终是清晰的屏幕表单，不将表格倾斜贴入模型。
手机默认采用底部浮层，多选时压缩浮层以留出可点选的教室区域。
展开、收起、关闭、浏览其他物件均不等于提交业务。

浮层显示当前班级、业务日期与来源物件。切换物件、学生、班级或日期前检查未保存修改；
用户拒绝放弃时保留原上下文。写入进行时不允许切换或重复提交。
关闭或换物件后，迟到的异步响应不得覆盖新浮层；班级切换失败也不能留下旧班级可操作状态。
传统后台的专业入口在新页打开，原班级场景保持，不自动赋予权限或触发操作。

### 场景多选与批量核对

考勤和五餐面板都支持“在场景里选学生”。点击人物切换选中状态，选择环与表格勾选同步。
支持跨名册分页选择；进入另一业务或切换班级时清空选择，重复ID和非当前名单ID被过滤。
考勤批量状态包含到园、缺勤、请假；批量请假仍必须有原因。
用餐按餐次把就餐、不就餐、不供餐应用到选中学生。

选择人物 → 应用到草稿 → 明确保存，是三个独立步骤。
选中人物、批量勾选、查看物件不能直接完成点名，也不能确认实际就餐。
保存仍使用原 `save_attendance` / `student_meals.save_class_meals`，不是第二套数据存储。

### 一日工作路线

教师工作板依次引导出勤核对、课堂计划、用餐核对、实际观察；
健康核对步骤仅在原专属权限允许时加入。每步显示实际登记状态，不设虚假完成率。
“已排课”不是“已上课”；打开一个入口不是完成任务；日志数量不作为教师考核指标。
未来日期仍禁止记录已发生事实，使用已有后端验证，前端也明确提示。

### 搜索、键盘与降级

搜索可查当前可见学生姓名/业务标识及物件名称；`/` 聚焦搜索，`?` 打开全部物件，
Escape 返回场景或关闭搜索；支持 Tab、方向键进入搜索结果和原生表单操作。
锚定标签与实际模型都可点击，标签具备文字说明和焦点状态。
WebGL失败或上下文丢失时，保留所有业务面板、完整名册和相同的权限/写入流程。
不为了修复3D渲染而放宽认证、数据权限或系统沙箱。

## 数据真实性

### 出勤不能由预计用餐人数反推

新读模型明确区分 `Present`、`Absent`、`Leave`、`Unknown`。
仅有已登记到园事实才计入 Present。没有考勤也没有请假记录时为 Unknown（待点名）。
分子是已登记到园，分母是当前可见在册学生；空名单的比例为 null，而不是 100%。
人数按当前名册交集统计，取消的记录排除；冲突时保持原业务中的缺勤、请假优先次序。
请假采用原业务一致的有效记录口径（未取消且未标记返校），不擅自改动原审批规则。

页面是以**当前启用名册**查看所选日期的记录，不是历史名册重建服务。
班级转入、转出后需要完整历史名册时，应另行定义快照需求，不能把当前名册冒充历史名单。

### 预计与实际独立

尚无班级就餐计划时，原接口提供的预计人数标注为“原膳食规则预估，尚未保存安排”。
没有确认实际的记录，实际人数显示破折号，不能显示为已就餐。
“确认五餐实际情况”有明确的人工确认步骤；未发生的餐次不可提前声称已经实际就餐。
未来日期仅能保存预计安排；原锁定、已确认变更原因、名单完整性和修订冲突规则全部保留。
不会自动修改采购、收货、发票、付款、退费或其他班级记录。

### 3D 是业务可视化，不是定位系统

教室为程序生成的卡通示意模型，尺寸、家具、座位、服饰与人物形象不是实测结果。
人物按名册稳定排布，状态环对应业务登记；这不是学生此刻在教室中的真实位置。
为控制渲染开销，精细版每页最多展示24个虚拟形象，但可以翻页查看全部可见学生。
80人名册分为24、24、24、8人四页；搜索或打开后一页学生时自动切到其所在页。
完整名册始终保留全部可见学生。页码是名册分组，不是教室分区或真实座位。
未接入人员定位、座位测绘、区域热力、午休监测、环境传感器或情绪识别；不显示伪实时指标。
教师形象为装饰模型，不代表某位教师的真实身份、当前在岗状态或出勤。

## 权限与写入安全

`classroom.require_user` 拒绝游客及停用账号；所有读写先调用 `_scope`，
复用 `attendance_scope.allowed_groups` 和原教师权限约束。
本次不新增或扩大任何角色。现有业务管理角色原有的跨班级范围保持不变。
Student、课表与学生日志使用权限感知的 `frappe.get_list`，与当前可见班级名单再次求交集。

健康资料依然只允许 Administrator 或 Tongjianyun Health Manager 且具备 DocType 读取权限的账号。
普通教师拿不到健康人数、诊断文字、病史或电话号码；健康详情不进入初始概要响应与3D标签。
一般成长记录排除 Medical 类型。登记文本在前端转义，成长写入转义 HTML，不渲染用户提供的脚本。

所有写接口仅接受 POST；浏览器通过当前登录会话及 Frappe CSRF Token 请求。
点名保存携带名册/考勤/请假版本摘要，在班级行锁后重新读取并比较；变化则提示重新核对。
此版本约束覆盖本工作台提交；系统内其他写入口仍遵循各自原有的并发控制规则。
就餐和健康分别复用原业务的 modified/revision 校验。
保存期间锁定对话框按钮；网络结果不明时提示先核对，不自动重放写请求。
读取失败、权限不足、无班级、无记录均有明确界面，不悄悄显示模拟值。
切换班级或日期时立即隐藏旧班级面板；读取尚未完成或失败时禁止从旧快照发起业务操作。

数据不写入 localStorage，不发送第三方分析服务；Three.js、OrbitControls 均复用应用已有本地资源。
页面可见且没有业务对话框时每60秒读取一次；页面隐藏时不轮询。
3D 静态模式在交互/尺寸变化时按需渲染；精细版装饰动画可关闭，后台不渲染，减少动态效果偏好优先。设置像素比上限并在退出时释放资源。
WebGL 失败时降级到普通业务入口，教师仍可使用表格完成管理。

## 部署

本次不新增 DocType、Custom Field、Property Setter、DDL 或数据迁移。
禁止为部署此页面运行 `bench migrate` 或修改上游应用。
把文件放入当前应用后，运行一次源代码导航集成；之后刷新缓存并优雅重载本 Bench 的 Web workers。
该重载不重启数据库、队列或其他应用。脚本会核实目标 Bench 路径和 gunicorn 命令。

```bash
cd /home/zyd/frappe/native-bench
env/bin/python apps/tongjianyun/deploy/classroom/install_entries.py
env/bin/python apps/tongjianyun/deploy/classroom/refresh_runtime.py
```

`install_entries.py` 是针对当前已有源码的幂等集成，不是数据库安装程序；
上游工作台源码结构变动时会拒绝盲目替换，须人工审阅。

也不对真实站点执行写入。覆盖 WebGL、桌面/手机、点名保存交互、五餐确认交互、
成长记录交互、健康入口、日期与班级切换、80人名册分页及每页24个精细形象上限、WebGL失败后的业务降级，

该脚本使用当前服务器已有的 Chromium 和 Debian `ws`；其它机器可用
`CLASSROOM_TEST_CHROME` 指向已安装的浏览器，不是应用运行时依赖。
浏览器测试的合成保存成功不能等同于已在生产数据库实际新增记录。

正式开始使用前，应由有权限的老师在真实业务中核对并提交当天数据；
这里不会为验收目的给真实幼儿补签到、填过敏史或确认尚未发生的餐次。

## 本期不扩展的业务及下一阶段

本期完成的是**既有班级业务的场景化入口与日常高频办理**，并非新增完整的业务套件。
课程新增/调整/冲突检查、请假撤回/返校、名册导入/转班，以及受权限控制的监护人原档案，
仍沿用原专业流程；提供明确入口，不冒称已经全部在3D页面内重写。
没有新的家长聊天、接送确认、午睡考勤、区域参与名单、硬件控制或自动风险识别。

下一阶段需按老师实际使用反馈选择高频流程做受控内嵌，并测量完成时间、出错和放弃率；
在测量前不宣称效率提升或“80%覆盖率”。实体教室测绘、区域事件记录与传感器接入必须

## 班级教师入口 V1（2026-09-23）

### 从应用首页进入

首页继续使用 Frappe 原生 `/apps`，不改其它应用图标与上游源码。
`hooks.py` 的 `app_home` 和 `add_to_apps_screen` 指向 `/tongjianyun-entry`。

登录后的入口由服务端每次根据当前账号重新解析：

| 账号情况 | 行为 |
| --- | --- |
| 有在岗教师关联，仅一个可见任教班级 | 303 临时跳转到该班 3D 工作台，携带 `workspace=teacher` |
| 有多个可见任教班级 | 展示本人任教班级卡片，不默认替老师选择第一个 |
| 教师兼具明确管理/保健角色且能进入原工作台 | 选择“班级教师”或“业务工作台”；其它岗位继续使用原业务页，不冒充新建了独立岗位工作台 |
| 单独 Business Operator、没有教师关联 | 保留原业务工作台，不推断其为教师或园长 |
| 有 Instructor 角色但关联不完整 | 展示本人关联检查；不填充其它班级，不自动授予权限 |
| 未识别到可用入口 | 明确提示管理员核对账号与关联，无模拟班级 |
| Guest、停用账号、Website User | Guest 转登录；停用或非园内工作账号拒绝访问 |

管理员没有真实任教关联时依然进原业务工作台。教师可以从场景右上角“切换工作入口”返回
`/tongjianyun-entry?choose=1`。只有一个班也能主动回到选择页；不使用长久缓存的301记住个人路由。
本期未新增默认身份/默认班级数据库字段，不保存跨账号的浏览器身份偏好。

### 教师身份不是一个前端角色标签

关联链：当前登录 User → `Employee.user_id`（Active）→ `Instructor.employee`（Active）→
`Student Group Instructor`（严格限定 parenttype=Student Group、parentfield=instructors）→
启用 Student Group，并与 `frappe.get_list` 的原有读取范围求交集。
同时要求已有 Student 与 Student Group 读取权限。姓名、邮箱中的“老师”字样、请求中的
user/role 参数、Business Operator 基础角色都不能单独建立任教身份。

配置检查仅输出当前账号的关联布尔值与可见班级，不返回其它人员、员工信息或学生隐私。
管理员应在原员工、教师、班级配置里明确维护关联，本次部署不替任何账号添加或修改关联。

### 服务端工作范围与已有权限的区别

教师入口的列表及写入不仅靠下拉框过滤。`classroom._groups('teacher')` 每次重新解析任教关联；
`_scope` 在实际读取或写入前再次核验班级。`get_overview`、`save_attendance`、`add_record`、
`get_health/save_health`、`get_meals/save_meals` 均携带并校验 workspace。
变更任教关系后，旧链接或旧面板不会继续获得该教师入口的写入权。

**workspace 是在既有账号权限之上的工作范围收窄，不是切换 Frappe 身份或全局撤权。**
此前获授权跨班级的 Business Operator/管理账号，仍保留原工作台/API 中既有的业务权限。
选择教师视图不等于撤销其后台权限，也不是让其变成另一个低权限账号。
如需全系统严格单班级授权，应另行审查现有角色及权限配置；本期不静默改变历史授权。

班级原点名、请假、五餐、课表、观察与健康规则继续使用现有后端。新增用餐适配接口只是
在原 `student_meals` 前验证工作范围，并去掉其返回值中跨班级的 groups 索引；不改原餐次状态、
版本校验、变更原因、未来日期或锁定规则。写入后只返回保存结果，不返回无关班级清单。
成长日志与健康功能仍按原权限启用，不为了让按钮可用而扩大角色。

### 入口和缓存安全

`profile` 只接受服务端已识别的 teacher/business；班级参数必须属于服务端任教交集。
所有跳转目标均为固定本地路由，由 `urlencode` 编码班级标识；不接受外部 next/redirect URL。
工作入口、配置提示与个人303跳转使用 `private, no-store` 和 `Vary: Cookie`，避免不同账号的入口缓存混用。
页面不嵌入敏感学生数据、不需要前端脚本才能选择班级；原登录、CSRF 和健康资料访问控制保持。
