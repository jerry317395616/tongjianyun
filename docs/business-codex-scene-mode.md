# 场景统一业务对话部署开关

本说明描述候选代码的路由能力，不表示任何生产站点已设置或已上线。

由运维在目标站点的可信服务器配置中显式设置
`business_codex_scene_mode: "business"`，可让场景内所有已通过原账号校验的用户，包括
既有 System Manager 和 Administrator，都选择 `business_chat` 通道。页面、HTTP 请求、
日期、餐次、班级和模型参数均不能设置此开关，也没有新增用户切换权限的界面。

- 该开关只选择通道，不自动创建私有任务目录、启动执行器、设置密钥或开通写入权限。
  提交仍取决于原 `business_codex_enabled`、已配置队列/执行器及当前账号的真实业务权限。
- 已有任务存储可用但执行器离线时，仍保留业务历史和停止入口，禁止新提交；未 provision
  时不可提交，且 `chat.mode` 仍为 `business`，不会自动切回 `admin_project`。
- 业务服务报错、权限拒绝或配置值非法都不触发管理员通道回退。只接受精确字符串
  `business`；未设置或值为 `null` 时保留旧站点的兼容路由，其他值视为配置错误。
- 这不是账号授权变更。`require_project_access`、原管理员接口和各业务原生权限未修改；
  业务写适配器原有的 Administrator 限制也未解除。切换界面通道不等于允许该账号执行任何操作。
- 该开关不是禁用所有旧管理员接口的服务器安全策略。已有管理接口仍执行其原权限检查；
  这里只改变统一场景 bootstrap 向网页提供的对话通道。

部署前应独立验证任务私有存储、队列、固定隔离执行器和业务授权，再刷新场景读取新的
bootstrap。隔离 QA 临时设置时应保存此配置键原本是否存在以及原值，结束后原样恢复；
不得将 QA 成功自动解释为生产已启用，亦不得通过添加角色解决路由或权限问题。

## 候选回归证据（2026-09-26）

完整后端回归，1094/1094 通过（包含本开关新增的 8 项测试）；前端组件回归 177/177
通过。测试验证明确启用后的管理员/教师路由、离线历史和取消、未配置执行器、非法配置、
服务异常、HTTP 不能切换通道，以及原项目权限保持不变。

这不是管理员真实网页上传或生产部署证据。真实网页上传→原生 File→业务任务→Codex→
原服务写入→SSE→左侧回显须在独立保留的旅程中验证；该旅程还须证明原非空食谱库
未被改动，以及所有真实执行/事务已经结束。生产配置本轮尚未修改。

## 周历实际回显与后续回归

`get_overview` 现在分别返回当天覆盖的 `recipes` 与自然周相交的 `week_recipes`。
两个查询都使用原生当前用户 `get_list` 权限和生命周期过滤；周日查看工作日食谱不会改变
用户所选日期，也不意味着周日供餐。聊天场景周历使用后者，并继续通过原 `get_recipe`
核对全部明细权限。旧接口缺字段、不可读、详情失败会明确失败，不降级为“空食谱”。

前端 `showBusinessView(recipe_week)` 只有对应日期/餐次的实际读取和渲染完成才确认
`rendered`；切壳、旧的保存前请求、迟到结果均不能作为成功。刷新只合并正在进行的同
上下文请求，不缓存已完成的结果。所有共享状态模块及 HTML 入口使用同一缓存版本。
本周有实际周末菜品/食材时自动显示七列，否则保留五列；空白占位不代表供餐。

新添的构造期 `BusinessWorker.read_observer` 仅观察真实附件/食谱读取回调成功后的
JSON 副本，忽略观察器返回值，回调前后均复核任务授权。默认 `None`，不改变生产路由、
权限、保存适配器或写事务；它证明服务读取成功，不证明模型理解、浏览器收到或业务完成。

上述合并后的 Linux/Frappe 强制只读完整回归 **1109/1109** 通过，前端全量（含
`test_meal_scene_state.mjs`）**191/191** 通过。隔离站点既有管理账号的实际只读 bootstrap
探针也确认 `business` 路由、周历权限和默认视图；执行器未启用时 `can_submit=false`，
持久配置摘要未变。真实上传旅程与生产上线仍需单独证明。
