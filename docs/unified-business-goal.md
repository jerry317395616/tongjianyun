## 本批实现

- 常用列表和明细接入原生办理，权限允许时新建或编辑，保留原服务校验、审批、并发与审计。
- `frappe_new` 可在场景内打开新单据。周食谱排除通用新建，避免重复周食谱。
- `capability_inventory()` 逐入口提供可用权限、需要单据、状态条件与未验收标记。
- 原生表单在聊天结束时保活；离开未保存表单必须确认。原生导航同步当前单据上下文。
- 展示请求与实际浏览器渲染区分；模型不再把 SSE 发出当作已展示/已保存。
- `business_blueprint`：Codex 生成安全数据方案，私有文件持久化，左侧预览，摘要绑定确认，再创建独立 Custom DocType。
- 新类型自动进入当前站点业务目录，可列表、新建、编辑，启用历史；初始仅 System Manager 权限，不授权删除。
- 不接受模型 HTML、脚本、任意 SQL、字段表达式、自动默认值或权限元数据。

## 未知业务边界

简单登记业务可通过方案直接创建。已保存方案不等于已启用；启用不等于已录入记录。
复杂子表、财务过账、库存动作、外部系统、专业审批需要源码扩展、权限测试和部署验证，不能由简单字段表冒充。
新建表使用 Frappe 原生 ORM 的 schema 同步，不开放通用 DDL，不覆盖已有类型，不自动迁移/删除历史数据。
DDL 不能保证事务回滚；失败必须核对结构。重复启用仅接受相同结构，不能删表重试。
