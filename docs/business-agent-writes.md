## 真实调用路径

右侧业务任务 → 原 RQ Worker → 共享隔离 Codex → 每任务工具代理 →
站点共享 `BusinessWriteLedger` → `FrappeWriteAdapter` 独立原账号事务 →
原 `classroom.save_attendance/save_meal` → 提交回执 → 关闭写连接 →
新连接完整来源回读 → 持久 selection 事件 → 左侧按当前账号重新读取。

既有明确的普通登记请求没有额外通用审批步骤。仍保留原来的日期、任教班级、完整名单、
真实学生、修订冲突、变更原因、实际餐次确认和审计规则。新增工具不是通用方法/SQL执行器。

## 收尾和失败边界

- 同站点所有任务共用一个私有账本；调用编号、规范化意图及班级日/每日汇总资源分别去重与互斥。
- 重复投递可回读当前事实，不再次保存；不明提交保留跨任务资源锁，不因换任务或call_id解除。
- Worker和新Web进程都使用 `BusinessExecutionRuntime` 组合原生退出与宿主事务证据。
  取消先封闭写入口，再撤销代理、停止原生进程，最后等待真实工具回调结束。
- close失败或宿主进程消失不代表数据库事务排空；保留active、返回固定未核实诊断，不能伪造终态。
- 可信factory明确无连接/副作用且尚未调用begin时的构造失败可证明没有执行，释放资源但不自动重试。
- 提交后回读失败不变成回滚。真实Frappe权限错误规范化为拒绝，不误报成可重试的502服务故障。
